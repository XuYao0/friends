# 《老友记》剧本 MD 格式规范（JSONL 解析参考）

本文档描述经过一次清洗 + 二次清洗后的 MD 文件格式特征，供编写 JSONL 转换器使用。

---

## 一、文件集合

路径：`screenplays/converted_chunks/老友记_1-10季剧本_by_episode/`

命名规则：`NNN_SXXEXX.md`（NNN 为三位序号，SXXEXX 为季集号）

总文件数：229 个，覆盖 S01E01 ~ S10E17（含若干合并集，详见第七节）。

---

## 二、文件结构

每个文件从上到下分为三段：

```
[元数据头部]          ← 集名、编剧、转录者等，不进入对话记录
[正文故事内容]        ← 场景、对白、动作交替出现
*[END]*               ← 独立一行，标志正文结束
```

`*[END]*` 之后的所有内容（页脚、导航、图片链接）均为非正文，解析时忽略。

---

## 三、元数据头部

正文开始前可能出现以下行，均不是对话，不进入 JSONL：

```
The One Where ...（集名标题）
Season X, Episode Y
Written by: ...
Teleplay by: ...
Story by: ...
Transcribed by: ...
Additional transcribing by: ...
Converted to HTML: ...
Minor additions and adjustments by ...
Special thanks to ...
```

**注意**：S02E07、S02E08、S02E10 的元数据头部包含 speaker 简写说明（见第八节）。

---

## 四、场景 / 舞台说明行

格式：`*[...]*`，独立一行。

### 4.1 场景标记（最常见）

```
*[Scene: Central Perk, everyone is there.]*
*[Scene: Monica and Chandler's apartment.]*
```

### 4.2 时间流逝 / 镜头切换

```
*[Time Lapse]*
*[Time lapse. Ross is now clearly drunk.]*
*[Cut to the hallway.]*
*[Cut to: Joey's apartment.]*
*[Flashback, year 1987.]*
*[Fade to Black.]*
```

### 4.3 片头片尾 / 广告（不含对话信息）

经二次清洗后，以下标记已规范化，大小写可能不统一：

```
*[Opening Credits]*      或  *[OPENING CREDITS]*
*[Commercial Break]*     或  *[COMMERCIAL BREAK]*
*[Closing Credits]*      或  *[CLOSING CREDITS]*
*[Ending Credits]*       或  *[ENDING CREDITS]*
```

解析时均视为无对话内容的场景节点。

### 4.4 边界模糊的 `*[...]*`

部分 `*[...]*` 内容描述的是动作而非地点，例如：

```
*[Cut to Chandler, who is looking confused.]*
*[Ross looks at Rachel.]*
```

解析器应将所有 `*[...]*` 统一作为 `scene` 字段内容，不区分是地点还是动作。

---

## 五、对白行

格式：`Speaker: utterance`

### 5.1 说话人格式

- **Title Case**（S01–S08 主流）：`Monica:`、`Ross:`、`Chandler:`
- **ALL CAPS**（S02E07、S02E08、S02E10 及部分集）：`MONICA:`、`ROSS:`
- 复合说话人：`Ross and Rachel:`、`All:`、`Joey, Chandler, and Ross:`
- 角色身份说明：`Ross's Mom:`、`The Presenter:`、`Man on TV:`、`Waitress:`

### 5.2 说话人简写映射（仅 S02E07 / S02E08 / S02E10）

| 简写 | 全称 |
|------|------|
| `CHAN` | `CHANDLER` |
| `RACH` | `RACHEL` |
| `MNCA` | `MONICA` |
| `PHOE` | `PHOEBE` |

解析器需在这三集中展开简写。

### 5.3 冒号不一定是说话人边界

以下情形中冒号属于台词内部，**不**分割说话人：

```
Chandler: Mental note: If Jill Goodacre offers you gum, you take it.
Ross: *(Doing the spinning)* Okay, Monica: Right foot red.
Chapter One: The One Where We Say Goodbye
My two greatest enemies Ross: Rachel Green and complex carbohydrates.
```

### 5.4 行内动作

说话人台词中可内嵌一或多个 `*(...)* ` 动作片段：

```
Ross: *(mortified)* Hi.
Monica: *(laughing)* No, I mean it! *(stops laughing)* Seriously.
Phoebe: *(singing)* Smelly cat, smelly cat...
```

解析器应提取 `*(...)* ` 片段到 `inline_actions` 字段，剩余文字作为 `utterance`。

### 5.5 空台词行（已知遗留问题）

部分集存在 `SPEAKER:` 后无内容的行，例如 `ROSS:`。二次清洗未删除这些行，解析器应识别并跳过或标记为 `empty_utterance`。

已知存在空台词的集数（来自一次清洗日志）：
S02E04、S02E07、S02E10、S02E14、S02E20、S02E21、S02E22、S02E23（`RYAN:`）

## 六、独立动作行

格式：`*(...)*`，独立一行，主语写在括号内。

```
*(They all stare, bemused.)*
*(Joey enters carrying a pizza.)*
*(Monica and Rachel exchange a look.)*
```

区别于行内动作：独立动作行单独成行，没有前置说话人。

---

## 七、终止标记

正文最后一行（在任何闭幕动作 / 片尾台词之后）：

```
*[END]*
```

**注意**：极少数文件可能保留了 `*[The End]*`、`*[THE END]*` 等变体（如 222_S10E11、223_S10E12），解析器应将所有 `*[.*[Ee][Nn][Dd].*]*` 及独立的 `THE END` 视为正文终止信号。

## 九、歌词 / 海报字幕 / 屏显文字

Phoebe 唱歌时，台词行一般有动作说明 `*(singing)*`，歌词作为说话人台词处理：

```
Phoebe: *(singing)* Smelly cat, smelly cat, what are they feeding you?
```

无说话人的屏显文字、海报字幕、标语等，若原文已用 `*(Song lyric: ...)*` 或 `*(Poster caption: ...)*` 包裹，作为独立动作行处理；否则作为 `unparsed_text` 标记人工复核。

## 十、已知剩余问题（解析器需容错）

以下问题经人工核对后确认仍存在于文件中，解析器应容错处理而非报错中断：

### 10.1 同音词混淆（未修复）
部分 `your/you're`、`too/to`、`there/their/they're` 混用残留，属语义问题，不影响格式解析。

### 10.2 不可还原的 Mojibake
以下字符无法确认映射，原样保留在文件中：
- `Y択now`（疑为 `Y'know`）
- `G抧ight` / `g抧ight`（疑为 `G'night`）
- `揝hhh` 等（含义不明）
- S01E17 结尾西班牙语片段中的多处损坏字符

### 10.3 `?` 残片
S03 各集存在少量孤立 `?`（来自 `?br>` 残片清除后遗留），不影响格式解析。

### 10.4 缺少开场 scene marker
以下集数正文从对白直接开始，没有显式 `*[Scene: ...]*`：
- `027_S02E03.md`（已在人工核对中标注）
- `043_S02E04.md` 附近

解析器遇到正文开头无 scene 行时，应以空字符串或 `""` 初始化 `scene` 字段。

### 10.5 嵌套转录者注记
少量舞台说明行（`*[...]*` 或 `*(...)* `）内含转录者第一人称评注，已在人工核对中逐条列出，二次清洗未能自动删除。解析器可原样纳入 `scene` 或 `inline_actions`。

### 10.6 `*[END]*` 后的残留内容
极少数文件（如 `119_S05E23.md` 行1225）在 `*[END]*` 之后仍有格式为 `*[...]*` 的转录者注记行，不属于正文，解析时忽略 `*[END]*` 后的所有内容。

## 十一、JSONL 输出字段约定

每条正文事件对应一个 JSONL 行，字段如下：

| 字段 | 类型 | 说明 |
|------|------|------|
| `season` | int | 季号（1–10） |
| `episode` | int | 集号（1–N） |
| `type` | str | `utterance` 或 `description` |
| `content` | object | 事件内容，结构由 `type` 决定 |
| `raw` | str | 原始行文本（含行内说明，未剥离） |
| `emotion` | str/null | 留空，不自动推断 |
| `reason` | str/null | 留空，不自动推断 |

`type=utterance` 时，`content` 包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `utterance_id` | int | 本集内对白顺序编号，从 1 开始 |
| `global_utterance_id` | int | 全剧连续对白编号，从 1 开始 |
| `speaker` | str | 说话人名 |
| `utterance` | str | 台词文本，已剥离所有行内 `*(...)*` / `*[...]*` 片段 |
| `inline_description` | list[str] | 可选字段；台词内部说明，按出现顺序排列 |

`type=description` 时，`content` 包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `description` | str | 独立 `*[...]*`、`*(...)*` 或其他被识别为说明的文本 |

转换规则：

- 遇到 `Speaker: utterance` 组合，输出 `type=utterance`。
- 遇到独立的 `*[...]*`、`*(...)*` 等说明，输出 `type=description`。
- 台词内部的 `*(...)*` / `*[...]*` 不单独成行，抽取到该 utterance 的 `content.inline_description`。
- 转换脚本默认以 append 模式写入 JSONL；按剧集顺序分批处理时，第一批可使用 `--overwrite` 初始化输出，后续批次使用默认 append。
