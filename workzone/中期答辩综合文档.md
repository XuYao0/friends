# 基于剧本叙事的长期对话情感识别基准与记忆增强 Agent 研究

## 1. 研究背景

对话情感识别是自然语言处理和情感计算中的重要任务。传统对话情感识别通常关注较短上下文内的情绪判断，例如根据当前句、前后若干轮对话或当前场景判断说话人的情绪。这类设定在许多日常交互场景中有效，但无法充分覆盖长期对话中常见的情绪理解问题。

在真实长期交互中，一个人的情绪往往不是由当前一句话单独决定的，而是受到长期人物关系、过往事件、未解决冲突、稳定性格、近期目标和隐藏压力共同影响。许多台词表面上可能是平静、玩笑、反讽或功能性表达，但其真实情绪需要结合较早发生的事件才能准确判断。例如，一个角色短暂的迟疑可能来自此前的关系裂痕；一句看似轻松的玩笑可能是在掩饰尴尬、内疚或恐惧；一次反常的沉默可能与数个场景之前的冲突有关。

因此，本研究关注的是长期叙事语境下的说话人真实情绪识别，而不是仅根据局部文本进行表面情绪分类。项目以 Friends 剧本为主要数据来源，构建长期对话情感识别基准数据集，并设计一个基于在线记忆构建和事件检索的情感识别 Agent 架构。

本研究不直接声称电视剧剧本完全等价于真实长期对话。剧本是一种带有叙事组织、角色连续性和丰富关系线索的文本材料，适合构造长期情绪理解任务。相比真实长期对话，剧本数据更容易获得、隐私风险较低、人物关系和事件发展更连续、标注证据更容易回溯。因此，本项目的定位是“基于剧本叙事的长期情绪理解基准”，其核心价值在于为长期上下文、显式记忆机制和在线情绪推理提供可控实验环境。

## 2. 研究目标

本项目现阶段包含两项核心工作。

第一，构建长期对话情感识别基准数据集。该数据集以完整剧本为输入来源，按剧情顺序组织台词、场景说明和动作描写，并从中筛选需要长期上下文才能较好判断情绪的候选样本。数据集的标注目标是说话人在目标台词时刻的真实情绪，而不是台词表面情绪、观众感受到的喜剧效果、听者对该台词的理解，或剧情功能意义。

第二，设计并实现基于智能体记忆的情感识别 Agent。该 Agent 按剧情顺序在线阅读剧本，在预测第 t 句台词情绪时，只能使用第 t 句及此前已经到达的信息。人物状态、事件摘要、人物关系、事件索引和详细事件记忆都必须在线增量构建，不能使用未来剧情或基于完整剧本预先生成的全局信息。

总体目标可以概括为：模拟一个广义 AI 智能体从头阅读一部长篇剧本，并在每个评测点结合此前剧情、人物关系、事件记忆和当前语境，对当前台词体现的说话人真实情绪做出可解释判断。

## 3. 任务定义

给定按时间顺序排列的剧本输入流：

```text
x_1, x_2, ..., x_t
```

其中输入可以包括场景说明、动作描写、说话人身份和台词文本。对于目标台词 x_t，系统需要输出说话人的情绪标签、对应强度，以及支持该判断的情感分析。

任务输出示例为：

```json
{
  "utterance_id": "string",
  "emotions": ["neutral"],
  "intensities": ["none"],
  "analysis": {
    "emotion_explanations": [
      {
        "emotion": "neutral",
        "intensity": "none",
        "reason": "brief reason for this selected label"
      }
    ],
    "observable_facts": [],
    "memory_evidence": [],
    "inferences": [],
    "uncertainties": [],
    "final_reason": "string"
  }
}
```

本任务具有三个关键约束。

第一，在线约束。预测第 t 句时，只允许使用第 t 句及其之前的信息。所有摘要、人物状态、关系状态、事件索引、详细事件记忆和 embedding 都必须由此前输入在线构建，不能根据完整剧本提前生成。

第二，真实情绪约束。标注和预测都以说话人的真实当前情绪为目标。若台词存在伪装、反讽、压抑、多重情绪或情绪转移，系统需要尽量解释其背后的真实心理状态，而不是简单读取字面情绪。

第三，可解释约束。模型不仅要输出情绪标签，还要说明判断依据，并区分可观察事实、历史证据支持的推断和仍然不确定的假设。该要求有助于分析模型是否真正利用了长期记忆，而不是仅凭局部语气或常识猜测。

## 4. 数据集构建思路

### 4.1 数据来源

本项目使用 Friends 剧本作为长期对话数据来源。Friends 具有稳定主角群、长跨度人物关系、反复出现的情感冲突和大量跨 episode 的人物状态变化，适合构造长期叙事理解任务。

剧本输入包括以下信息：

1. 台词文本。
2. 说话人身份。
3. 场景说明。
4. 动作描写或行内描述。
5. episode、scene 和 utterance 顺序标识。

Agent 输入可以包含这些可观察信息，因为它们类似真实对话中可以被观察到的环境线索。但 Agent 不应直接获得完整人物表、全局人物关系图、章节总结或未来剧情信息。人物关系、事件和长期状态需要在阅读过程中逐步构建。

### 4.2 长期依赖样本筛选

为了证明数据集确实考察长期信息，而不是只依赖当前台词或短程上下文，本项目计划对样本进行分层。候选样本可以分为以下几类：

1. 局部可判断样本：当前台词、说话人和短窗口上下文已经足以判断情绪。
2. 中程依赖样本：需要当前场景或相邻场景内的上下文才能判断。
3. 长程依赖样本：需要较早 episode、较早 scene 或长期事件记忆才能判断。
4. 人物关系依赖样本：需要理解角色之间的长期关系、冲突、亲密程度或权力关系。
5. 性格与行为模式依赖样本：需要理解角色长期形成的稳定行为模式、价值观、自我形象或脆弱点。
6. 歧义样本：即使给出较长上下文，不同标注者或模型仍难以稳定判断。

筛选长期依赖样本的一个可行方法是比较短上下文标注器与长上下文标注器的分歧。若短上下文标注器不确定或误判，而长上下文标注器稳定一致，并能指出历史证据，则该样本可以作为长程依赖候选。若短上下文已经稳定判断，则归入局部可判断样本。若长上下文标注仍不一致，则标为歧义样本或剔除。

### 4.3 标注协议

标注阶段可以采用 LLM-assisted 或 silver-label 流程。标注时可以保留电视剧人物原名，并向强 LLM 提供当季或当集剧情概述、目标台词附近对话片段和必要历史上下文，以利用模型已有的角色知识和剧情知识提高标注质量。

但该流程需要明确说明：生成的是 LLM-assisted silver label，而不是完全人工 gold label。为了避免标注协议和被评测方法之间形成循环偏置，标注阶段不应使用最终 Agent 的专属记忆机制。更合理的方式是使用独立、透明、固定的标注输入协议，例如人物原名、剧情概述、当前对话窗口和必要历史上下文。

对于某些隐藏情绪，后续剧情揭示的信息可能有助于确定真实情绪。例如角色在 t 时刻表现反常，但原因在后续才揭示。标注时可以利用后续信息辅助判断 latent emotion，但需要区分四类证据：

1. 真实情绪标签。
2. t 时刻可观测证据。
3. 后续剧情证据。
4. 外部知识或预训练知识证据。

这样可以避免把完全不可由 t 时刻信息推断的标签混入普通在线识别评测。对于在线 Agent 主实验，预测时仍只能使用截至 t 时刻的信息。

### 4.4 原名与匿名化问题

保留人物原名有助于标注质量，因为强 LLM 可能掌握 Friends 的角色和剧情知识。但在模型评测中，人物原名也会引入参数化知识泄漏风险。模型可能依赖预训练中记住的角色关系和剧情，而不是从给定对话中构建记忆。

因此，实验中应考虑报告原名版本与匿名或别名版本的对照。至少需要在误差分析和实验讨论中单独说明预训练知识带来的偏置。若研究目标是验证 Agent 记忆机制，匿名化版本更能检验模型是否真的依赖在线构建的记忆。

## 5. 情绪标签体系

### 5.1 标签设计原则

本项目不直接采用某个理论家的完整基础情绪表，也不直接使用 Plutchik 情绪轮中的 24 个强度词作为标签。当前采用的是面向 Friends 长期对话情感识别任务的基本情绪集合，并为非 neutral 情绪额外标注强度。

标签保留原则包括：

1. 该情绪是否只是另一个情绪的强弱变化。
2. 该情绪是否只是其他标签的混合，且用多标签表达更自然。
3. 该情绪是否具有独立 appraisal structure，即独立的触发条件和心理评价结构。
4. 是否存在常见场景，使它是最自然的单一标签，而其他标签会明显丢失信息。
5. 它在 Friends 长期对话中是否足够常见，标注者或 LLM 能否稳定区分。

基于这些原则，项目保留了 contentment、relief、interest、contempt、shame、guilt 和 embarrassment 等标签。它们虽然不一定都属于传统六大基础情绪，但在长期对话中具有独立解释价值。例如 contentment 表示需求满足后的安稳舒适，relief 表示坏结果解除后的放松，contempt 表示居高临下的贬低性评价，shame、guilt 和 embarrassment 则分别对应自我价值受损、行为责任归因和轻度社交暴露。

### 5.2 当前标签集合

当前可用情绪标签如下：

| 标签 | 中文 | 含义 |
| --- | --- | --- |
| anger | 愤怒 | 被冒犯、被阻碍、不公对待或目标受损时的对抗性情绪。 |
| disgust | 厌恶 | 对对象、行为、想法或情境产生反感、排斥或远离倾向。 |
| fear | 恐惧 | 面对威胁、危险、惩罚、损失或坏结果预期时的防御性情绪。 |
| happiness | 快乐 | 一般正向愉悦、高兴、开心或愿望满足。 |
| surprise | 惊讶 | 现实突然偏离预期时的定向反应，可正向、负向或中性。 |
| sadness | 悲伤 | 失去、失败、分离、拒绝、失望或关系受损引发的低落。 |
| contentment | 满足 | 需求被满足、处境舒适安稳、没有急迫未满足需求时的平静正向情绪。 |
| relief | 如释重负 | 先前威胁、压力、担忧或坏结果预期解除后的放松性正向情绪。 |
| interest | 兴趣 | 注意被对象、信息、人物或可能性吸引，并想继续了解、观察或参与。 |
| contempt | 轻蔑 | 认为对象愚蠢、低劣、不值得尊重或可笑时的贬低性情绪。 |
| shame | 羞耻 | 自我形象、身份或价值暴露出缺陷时产生的自我否定和隐藏倾向。 |
| guilt | 内疚 | 认为自己做错事、伤害别人或违反责任时产生的自责。 |
| embarrassment | 尴尬 | 轻度社交失误、失态、被撞见、私人信息暴露或场面不合适引发的不适。 |
| neutral | 中性 | 无明显情绪，或证据不足以判断具体情绪。 |

强度标签包括：

| 强度 | 中文 | 含义 |
| --- | --- | --- |
| low | 弱 | 情绪存在但轻微。 |
| medium | 中 | 情绪明确可识别，但未达到强烈爆发或失控。 |
| high | 强 | 情绪强烈，通常伴随明显爆发、强烈行动倾向或高度行为表现。 |
| none | 无 | 仅用于 neutral。 |

标注规则要求 emotions 与 intensities 一一对应。非 neutral 情绪的强度必须为 low、medium 或 high。若标注为 neutral，则 emotions 必须为 `["neutral"]`，intensities 必须为 `["none"]`，且 neutral 不能与其他情绪并列。

### 5.3 理论依据

本项目参考 Ekman、Izard 和 Plutchik 的基础情绪理论，但不把任何一个理论体系视为直接决定标签集合的权威。

Ekman 的理论强调面部表情的跨文化识别一致性，早期基础情绪包括 anger、disgust、fear、happiness、sadness 和 surprise。该理论为常见基础情绪提供了跨文化表达依据。

Izard 的 differential emotions theory 强调情绪的发展时间线、神经生物基础、表达模式和动机功能。其理论关注 fear、anger、shame、contempt、disgust、guilt、distress、interest、surprise 和 joy 等离散情绪，对本项目保留 interest、shame、contempt 和 guilt 等标签有启发意义。

Plutchik 的情绪轮从进化适应功能出发，把情绪理解为与典型刺激、认知判断、行为反应和生存功能相连的模式。其八个基础情绪包括 joy、trust、fear、surprise、sadness、disgust、anger 和 anticipation，并通过强度梯度和复合情绪组织情绪空间。该理论有助于解释为什么长期情绪理解需要关注人物目标、威胁、关系和行为倾向。

综上，本项目的标签体系既吸收基础情绪理论的稳定性，又根据长期对话任务需求保留若干社会性和自我意识情绪。

## 6. 记忆增强 Agent 架构

### 6.1 总体思路

AC Agent 是一个面向在线长期对话情感识别的原型框架。其核心思想是：外层采用确定性 workflow 保证在线处理顺序，内层通过 LLM tool-calling 实现事件检索、事件读取、记忆更新和情绪推理。

Agent 按剧情顺序不断接收剧本输入。预测某个评测点时，系统只向 Agent 提供当前台词及其之前已经到达的信息。Agent 需要利用在线构建的人物状态、当前事件、事件索引和详细事件记忆来辅助情绪识别。

基本流程如下：

1. 接收当前台词及可观察上下文，包括说话人、台词文本、场景说明和动作描写。
2. 将压缩后的人物状态放入当前推理上下文，作为长期稳定背景。
3. 输入当前 scene 内的当前事件摘要，提供近距离上下文。
4. 通过工具调用访问事件记忆，先查询事件索引，再决定是否读取少量详细事件描述。
5. 构建情感推理 prompt，要求 LLM 输出情绪标签、强度和结构化分析。
6. 在预测后根据当前输入更新人物状态、关系状态、事件索引、详细事件和当前事件。

### 6.2 确定性外层 workflow

首版运行策略是“确定性外层 workflow + 分支内 LLM tool-calling”。

数据源 `FriendsTranscriptChunkSource` 按文件顺序读取 `description` 和 `utterance`。其中 description 进入 transcript buffer，但不计入 batch size；普通 utterance 进入 transcript buffer，并计入 batch size。

当未遇到评测点且累计到 `batch_size` 条 utterance 时，系统产出 `status = "update_memory"` 的 chunk，用于批量更新记忆。当读到 `long_context_selected = true` 的 utterance 时，系统产出 `status = "label"` 的 chunk，目标台词为该 utterance。

`WorkflowRunner` 根据 chunk status 分派任务：

1. `status = "update_memory"`：进入 `MemoryUpdateLoop`，根据当前 batch 更新记忆。
2. `status = "label"`：进入 `LabelLoop`，进行情绪识别，并保存预测结果。

默认 workflow 会处理完整个 `screenplays/friends_records_renamed_with_selected.jsonl`，读到 EOF 后结束。若评测点落在 batch 中间，系统只能使用截至该评测 utterance 的信息，不能使用评测点之后的 utterance。

### 6.3 Tool-calling 内层循环

内层 LLM 可以调用三类核心工具：

1. `search_events(query, characters, keywords, top_k)`：检索可见在线事件记忆，返回候选事件索引。
2. `read_event(event_id)`：读取某个事件的详细描述。
3. `update_memory(delta)`：把人物、关系、事件和当前事件变化写入记忆状态。

工具调用由 `ToolRegistry` 和 `ToolExecutor` 统一管理。LLM 每轮可以选择调用工具，也可以在不再需要工具时返回最终结果。工具结果会作为 tool message 回填给下一轮 LLM 输入，使模型能够基于检索结果继续推理。

这种设计有两个好处。第一，检索和记忆更新行为可记录、可复现、可消融。第二，系统不会把全部历史文本无差别塞入 prompt，而是要求 Agent 显式决定要检索什么、读取什么，以及如何使用记忆。

### 6.4 情绪标注分支

`LabelLoop` 负责在评测点预测目标台词的真实情绪。其输入包括：

1. `target_utterance_id` 和目标台词。
2. 当前 transcript chunk。
3. 当前 chunk 的说话人集合。
4. 当前事件摘要。
5. 相关人物状态。
6. 已检索的详细事件。
7. 情绪标签 schema。

标注分支的推荐流程为：

1. 检查目标台词、transcript、相关人物状态和当前事件。
2. 判断是否需要历史事件；如果需要，调用 `search_events`。
3. 如果事件索引摘要不足，再调用 `read_event`。
4. 形成情绪预测和分析。
5. 如果当前 transcript 产生新的长期或当前事件信息，在最终回答前最多调用一次 `update_memory`。
6. 返回固定 JSON，程序解析为 `EmotionPrediction` 并校验。

最终输出应包含 emotions、intensities 和 analysis。analysis 中至少区分 observable_facts、memory_evidence、inferences、uncertainties 和 final_reason。

### 6.5 记忆更新分支

`MemoryUpdateLoop` 负责从一批在线到达的 utterance 中抽取人物状态、关系状态、事件和当前事件变化，输出可合并的 memory delta。

记忆更新只应记录当前 batch 中可观察到或可谨慎推断的信息。它不输出完整人物状态，而是输出 patch/delta。事实、推断和不确定假设需要显式区分，不能把不确定假设静默升级为事实。

主实验设置中，记忆更新不注入 gold 情绪标签。可以另设带标签反馈的对照组，即额外使用标注情感和标注分析更新记忆，以检验监督式情感反馈是否能提升后续识别效果。但这类设置必须单独报告，不能与主实验混淆。

## 7. 记忆结构设计

AC Agent 的记忆结构包括人物状态、事件索引、详细事件记忆和当前事件四类。

### 7.1 人物状态

人物状态是高度压缩的长期记忆，预测时可以全量输入。其代码结构为 `CharacterState`，主要字段包括：

1. `character`：人物名或匿名 id。
2. `version`：人物状态版本。
3. `recent_events`：近期对人物有影响的事件摘要。
4. `short_term_traits`：短期状态和临时倾向，例如当前目标、压力、需求、情绪基调、近期解释倾向。
5. `long_term_traits`：长期稳定特点，例如人格倾向、行为模式、价值观、自我形象和稳定脆弱点。
6. `relationships`：人物视角下的人际关系状态。

人物状态采用 `MemoryItem` 列表存储。每条 `MemoryItem` 包含文本、证据引用、事实类型和状态。事实类型包括 fact、inference 和 uncertain。这样可以在同一 schema 中保存事实、推断和不确定假设，同时在 prompt 中要求模型显式区分它们。

### 7.2 事件索引

事件索引用于快速判断哪些历史事件可能与当前台词相关。其代码结构为 `EventIndex`，主要字段包括：

1. `event_id`：事件 id。
2. `scene_id`：事件所属 scene。
3. `time_label`：可读时间标签。
4. `location`：地点。
5. `characters`：涉及人物。
6. `keywords`：检索关键词。
7. `short_summary`：短摘要。
8. `importance`：重要性，建议 1 到 5。
9. `knowledge_scope`：谁知道这件事。
10. `detail_id`：对应详细事件记忆 id。

首版检索使用关键词、人物、地点和摘要的轻量检索。后续可以加入 embedding 或混合检索，但 embedding 必须在事件写入后生成，不能对完整剧本提前生成。

### 7.3 详细事件记忆

详细事件记忆用于保存更完整的历史事件描述。其代码结构为 `EventDetail`，字段包括 detail_id、event_id、description、scene_id、time_label、location 和 knowledge_scope。

详细事件不默认进入 prompt。Agent 必须先调用 `search_events`，从事件索引中获得候选事件，再决定是否调用 `read_event` 读取详情。每个评测点可读取的详细事件数量有硬上限，默认 `max_read_events = 3`。该设计避免系统退化为把长历史全文塞入 prompt。

### 7.4 当前事件

当前事件是当前 scene 内已经发生内容的近距离摘要。其代码结构为 `CurrentEventState`，字段包括 scene_id、time_label、location、summary、characters 和 knowledge_scope。

当前事件始终作为近距离上下文输入 Agent，其优先级高于长期详细事件。当前事件只能包含截至当前 utterance 的内容。scene 切换时，当前事件需要重置或压缩归档为长期事件记忆，这是后续需要继续完善的策略。

### 7.5 记忆合并策略

首版记忆合并由程序规则完成，而不是额外调用 LLM。LLM 在调用 `update_memory` 前决定是新增还是修正，程序层只执行结构化操作。

当前开放给模型的操作包括：

1. `append`：新增一条 `MemoryItem`。
2. `update`：用新条目替换已有条目，需要提供目标下标。

程序内部保留 `supersede` 操作，但不暴露在模型可见 tool schema 中。每次应用 delta 后，全局 memory version 递增，并记录来源 utterance。当前暂不做自动去重、冲突消解或压缩，这些是后续扩展方向。

## 8. 当前实现进展

项目当前已经形成 AC Agent 的首版原型框架，主要实现包括：

1. `WorkflowRunner -> MemoryUpdateLoop/LabelLoop -> ToolExecutor -> ToolRegistry/AgentTool` 主执行路径。
2. `FriendsTranscriptChunkSource` 和 transcript 组织模块，可按原始顺序读取 description 和 utterance。
3. 结构化 `MemoryState`，覆盖人物状态、关系状态、事件索引、详细事件和当前事件。
4. `JsonMemoryStore`，支持本地 JSON 形式保存完整 memory。
5. `JsonlPredictionStore`，支持将情绪预测结果追加保存为 JSONL。
6. `JsonlTraceWriter`，支持保存每个 chunk 的 LLM 输入输出、tool result 和最终预测。
7. `search_events`、`read_event`、`update_memory` 三个核心工具。
8. 基于关键词、人物、地点、摘要和重要性的事件检索。
9. DeepSeek OpenAI-compatible chat completions 接入，真实运行需要 `DEEPSEEK_API_KEY`。
10. YAML 配置入口 `build_workflow_runner_from_config()`，可从 `acagent/configs/*.yaml` 构建完整 runner。
11. 默认输出目录 `acagent_outputs/default/`，包含 memory、predictions 和 traces。
12. 当前测试状态为 55 passed，说明核心程序路径已有基础测试覆盖。

运行方式示例：

```bash
PYTHONPATH=acagent/src uv run python -c 'from acagent.runner import build_workflow_runner_from_config; build_workflow_runner_from_config("acagent/configs/default.yaml").run()'
```

## 9. 实验设计

### 9.1 主评测对象

本项目的核心评测对象是情感标签和情感分析质量。记忆机制是提升情感识别的手段，记忆内容本身暂不作为主评估指标。但为了分析错误来源和验证机制有效性，需要保存记忆访问轨迹，并可在后续进行记忆质量抽查或案例分析。

每次情绪预测需要记录：

1. 输入的人物状态版本。
2. 搜索查询。
3. 返回的事件索引。
4. 实际读取的详细事件 id。
5. 最终进入 prompt 的记忆内容。
6. LLM 原始输入输出。
7. 工具调用结果。
8. 最终预测。

这些 trace 可用于复现实验、消融分析和错误回溯。

### 9.2 对照实验

为了区分不同上下文和记忆机制的贡献，实验应至少包含以下对照：

1. 当前句或短窗口上下文模型：只使用目标台词和局部上下文。
2. 长窗口上下文模型：使用更长 transcript，但不使用显式结构化记忆。
3. 摘要记忆模型：使用在线摘要作为历史信息。
4. 检索记忆模型：从历史事件中检索相关内容。
5. 结构化人物和事件记忆模型：使用人物状态、关系状态、事件索引和详细事件。
6. 完整 AC Agent：使用确定性 workflow、tool-calling、检索、读取和记忆更新。

此外，还可以设置记忆更新方式的对照：

1. 无标签反馈更新：只使用当前输入和可观察上下文更新记忆。
2. 带标签反馈更新：额外使用标注情感和标注分析更新记忆。

两类设置必须分开报告，避免把标注信息注入主实验设置。

### 9.3 评测指标

情绪标签可以使用分类指标评估，例如 accuracy、macro-F1、micro-F1、多标签 F1 或 exact match。由于当前 schema 支持多情绪标签和强度，评测时可分别统计：

1. 情绪标签是否正确。
2. 情绪强度是否正确。
3. neutral 与非 neutral 是否区分正确。
4. 主情绪是否正确。
5. 多标签组合是否完全匹配。

情感分析文本可以使用 LLM-as-a-judge 评估。Judge prompt 应重点判断：

1. 分析是否支持情绪标签。
2. 是否引用有效上下文证据。
3. 是否存在与已知剧情冲突的解释。
4. 是否过度臆测。
5. 是否区分可观察事实、历史推断和不确定假设。

Judge 输出可以包括 label_correctness、analysis_quality、evidence_use、conflict_with_context 和 comments 等字段。

### 9.4 长期依赖验证

为了证明长期记忆机制确实带来收益，需要对样本进行分层报告。特别是应比较不同模型在局部可判断样本和长程依赖样本上的表现差异。

理想结果是：短窗口模型在局部样本上表现尚可，但在长程依赖、人物关系依赖和性格依赖样本上明显下降；显式记忆 Agent 能在这些样本上取得更好的标签准确率和分析质量。若完整 Agent 的提升主要发生在长程依赖样本上，则可以更有力地支持“显式记忆机制对长期情绪识别有帮助”的论点。

## 10. 研究贡献

本项目预期贡献包括以下几个方面。

第一，提出一个基于剧本叙事的长期对话情感识别任务设定。该设定强调在线阅读、长期记忆、真实情绪和可解释推理，区别于只关注短上下文或局部语义的传统对话情感识别。

第二，构建 Friends 长期情绪理解基准数据集。数据集以完整剧本为基础，保留场景说明、动作描写、说话人和台词顺序，并通过短上下文与长上下文分歧筛选长期依赖样本。

第三，设计适合长期对话的情绪标签体系。该体系结合 Ekman、Izard 和 Plutchik 的基础情绪理论，同时根据长期对话任务需求保留若干社会性和自我意识情绪，并引入强度标注。

第四，提出 AC Agent 原型架构。该架构以在线增量记忆为核心，结合人物状态、事件索引、详细事件和当前事件，通过 tool-calling 实现可控检索、读取和记忆更新。

第五，提供可复现实验日志。系统记录每个评测点的记忆版本、工具调用、检索结果、读取事件、LLM 输入输出和最终预测，支持消融实验、错误分析和后续改进。

## 11. 当前问题与风险

项目仍存在若干需要在后续工作中重点解决的问题。

第一，silver-label 标注质量需要验证。LLM-assisted 标注可以降低成本，但可能存在模型偏见、过度利用预训练知识和复杂情绪判断不稳定等问题。后续需要通过人工抽查、多标注器一致性或 Judge 机制提升可信度。

第二，原名带来的参数化知识泄漏需要控制。Friends 是知名剧集，模型可能已经记住角色关系和剧情。后续应考虑匿名化版本，或至少报告原名与匿名版本的差异。

第三，记忆自动更新可能产生噪声。当前没有自动去重、冲突消解和压缩策略，长期运行后人物状态可能膨胀或包含重复、过时、冲突信息。后续需要实现 memory compression 和更稳定的更新策略。

第四，事件检索首版较简单。当前主要依赖关键词、人物、地点、摘要和重要性。对于隐含关系、语义相似和跨场景呼应，关键词检索可能不足。后续可加入在线生成的 embedding 和混合检索。

第五，评测点选择需要进一步严格化。需要确保长程依赖样本确实无法由短上下文稳定判断，并明确区分可推断的长期情绪与 t 时刻完全不可观测的隐藏情绪。

第六，情感分析的自动评估具有主观性。LLM-as-a-judge 虽然实用，但需要固定 prompt、控制输入、记录 judge 输出，并通过人工抽查验证其可靠性。

## 12. 后续计划

后续工作可以分为数据、模型、评测和系统完善四条线。

数据方面，需要继续清洗 Friends 剧本，完善 utterance、description、scene 和 episode 的结构化字段；完成长期依赖候选样本筛选；构建 LLM-assisted 标注任务；对标注结果进行一致性检查和人工抽查；形成可用于实验的训练、验证和测试划分。

模型方面，需要完善 AC Agent 的 prompt、工具预算和记忆更新策略；实现更稳定的 memory compression；探索 target-only memory 变体，即评测点只输入目标单句，所有历史信息必须来自在线记忆；比较 cheap_update_model 和 reasoning_model 的成本与效果。

评测方面，需要实现短窗口、长窗口、摘要记忆、检索记忆、结构化记忆和完整 Agent 的对照实验；按局部、中程、长程、人物关系和性格依赖样本分层报告；使用 LLM-as-a-judge 评估情感分析质量；开展错误分析和案例研究。

系统方面，需要继续清理早期骨架代码，统一主 workflow；完善运行恢复机制；增强 trace 分析工具；改进失败预测和 JSON 解析错误处理；保证默认 workflow 能稳定完成小规模真实模型运行，并逐步扩展到完整数据集。

## 13. 中期总结

截至目前，本项目已经明确了研究问题、任务边界、情绪标签体系、数据构建思路和 Agent 架构，并实现了 AC Agent 的首版程序框架。当前系统能够按剧本顺序读取 Friends JSONL 数据，区分记忆更新 chunk 和情绪标注 chunk，通过 LLM tool-calling 调用事件检索、事件读取和记忆更新工具，并将记忆、预测和完整 trace 保存到本地文件。

本阶段的核心进展不是单一模型性能提升，而是建立了一个可以系统研究长期对话情绪理解的实验框架。该框架将“长期上下文是否有用”“显式记忆是否优于长窗口”“人物状态和事件记忆如何帮助情绪识别”“模型分析是否真正引用历史证据”等问题转化为可运行、可记录、可消融的实验流程。

下一阶段的重点是提高数据标注质量、完成长期依赖样本分层、运行系统性对照实验，并通过定量指标和案例分析验证记忆增强 Agent 在长期情绪识别任务中的有效性。
